基于 LangChain + DeepSeek V4 的多路召回智能法律助手，支持法律知识问答与合同风险自动审查。

## 功能简介

- **法律智能问答**：自然语言提问，Agent 自动检索法规库并生成带法条引用的专业回复
- **合同风险审查**：上传 PDF / Word 合同，自动逐条分析并输出结构化审查报告（高/中/低风险等级 + 修改建议）
- **风险条款可视化**：合同原文中以红 / 黄 / 灰三色高亮标注风险点，悬停查看详情、点击钉住修改建议
- **对话历史管理**：支持创建、切换、搜索（拼音模糊匹配）、重命名、删除对话，本地 SQLite 持久化
- **流式交互**：逐字打字机输出、思维链可视化、随时停止生成、多对话并发隔离

## 快速启动

### 1. 克隆并进入项目

```bash
cd Law-AI-Assistant
```

### 2. 配置 API Key

```bash
cd backend
cp .env.example .env
```

编辑 `.env`，填入三个 API Key：

```env
DEEPSEEK_API_KEY=sk-xxxxxxxx
TAVILY_API_KEY=tvly-xxxxxxxx
YUANDIAN_API_KEY=xxxxxxxx
```

### 3. 启动后端

```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux

pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 初始化数据库（首次运行必须执行）
python -m app.init_db

# 启动服务
uvicorn app.main:app --reload --port 8000
```

后端启动后访问 http://localhost:8000/docs 可查看 Swagger 接口文档。

如需上传旧版 DOC，还需安装 [LibreOffice](https://www.libreoffice.org/download/)，并按下方“DOC 本地转换配置”设置可执行文件；没有安装时 PDF / DOCX / TXT 不受影响。不需要安装 Microsoft Word，也不使用云端文件转换服务。

### 4. 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端启动后访问 http://localhost:5173 即可使用。

## 后端开发检查

在 `backend/` 目录中激活虚拟环境后，安装开发依赖并执行：

```bash
pip install -r requirements-dev.txt
```

测试使用临时数据库和占位 API Keys，禁用 `.env` 读取及外部服务连接，无需启动 Ollama 或配置真实 API Keys。Windows 事件循环内部通信所需的套接字对保留可用。

默认测试通过替身检查 DOC 转换的超时、并发、配置隔离及失败清理，不启动外部 Office。已安装 LibreOffice 时，可额外显式运行真实转换测试（PowerShell 示例）：

```powershell

python -m pytest tests/test_doc_conversion_integration.py -q
Remove-Item Env:LAW_AI_TEST_LIBREOFFICE
```

该测试临时生成带中文、横纵合并及嵌套表格的 DOCX，经 LibreOffice 导出真正的 DOC，再验证两类上传、结构坐标、临时历史保存及重新审查；未指定上述变量时跳过。不读取个人合同、不调用真实模型，也不写入应用历史库。

### 后端日志

后端通过标准库 logging 输出应用日志，在 `backend/.env` 中设置 `APP_LOG_LEVEL` 后重启服务即可生效，默认为 `INFO`，可选 `DEBUG`、`WARNING`、`ERROR`、`CRITICAL`。

- `INFO`：咨询与审查的开始、完成，以及输入长度、风险点数量等元数据。
- `DEBUG`：工具名称、召回数量、JSON 修复及流式阶段等详细追踪，不记录咨询正文、模型回复、工具参数或合同内容。
- `WARNING`：检索服务降级、引用匹配失败、历史思维链格式损坏等可恢复问题。
- `ERROR`：请求处理失败、数据库操作异常或审查 JSON 无法解析等问题。

应用日志统一写入标准错误流，包含时间、级别和模块名；重复初始化不会增加控制台处理器，也不接管 Uvicorn 或第三方库的日志配置。应用控制台的异常输出保留异常类型、文件、行号及异常链，省略异常消息、源码行和局部变量，避免第三方异常携带敏感正文或 API Keys。此保护仅覆盖应用自己的控制台输出，不等于日志中的任意字符串都已自动脱敏；对客户端的安全提示另由 API 错误边界负责。

`python -m app.init_db` 的命令行进度输出仍保留，未将其作为服务请求日志改造；日志文件持久化、轮转及收集可在部署时另行配置。

### 错误响应与排查

API 不直接返回异常正文。已知异常按类型和上游 HTTP 状态映射为固定中文提示，不通过异常字符串猜测原因；无法可靠识别的错误统一降级为“服务暂时不可用，请稍后重试。”。

| 情况 | HTTP 状态（响应开始前） | 用户处理建议 |
|------|------------------------|-------------|
| 网络或 TLS 连接异常 | 503 | 稍后重试，持续失败时联系管理员检查连接 |
| 服务超时 | 504 | 稍后重试 |
| 上游认证或权限异常 | 503 | 联系管理员检查服务配置，不要求本站用户重新登录 |
| 上游限流或额度不可用 | 429 | 稍后重试，持续出现时联系管理员 |
| 上游服务错误或拒绝请求 | 502 | 稍后重试，或缩短输入后重试 |
| 任务达到处理步骤上限 | 503 | 缩小问题范围后重试，不改变原有调用上限 |
| 审查报告无法解析 | 502 | 重试审查，持续失败时联系管理员 |
| 文件解析失败 / 不支持的格式 | 400 | 检查文件是否损坏或加密，转换为支持的格式 |
| 未知内部异常 | 500 | 稍后重试，由管理员查看服务端日志 |

新分类的普通错误响应保持字符串 `detail`，并附带稳定 `code`；参数校验失败返回 422，不再回显原始输入，OpenAPI 文档同步使用该结构。原有“会话不存在”404 和文件超限 413 提示保持不变。

SSE 开始后的失败无法再修改 HTTP 状态，因此仍通过 `type: "error"`、`message` 和 `code` 报告，不追加正常 `done` 帧。前端继续通过原有错误回调展示及保存失败气泡；主动停止不当作网络错误。浏览器连接失败使用固定中文提示，而不是异常原文。

工具调用异常返回明确的“未完成”提示，不把服务故障伪装成“查无结果”；专业法律检索在补充路径失败时保留已有法条。错误响应不携带供应商正文、API Keys 或内部路径，服务端应用日志保留错误类别和脱敏调用栈用于定位。第三方库自身日志、正常业务内容及旧数据库中已经保存的原始错误不在本次自动清洗范围内。

## 使用方式

1. **法律问答**：在输入框输入法律问题（如"民法典第 585 条是什么""试用期被辞退有赔偿吗"），按回车或点击发送按钮
2. **合同审查**：点击输入框左侧 + 按钮选择 PDF / DOC / DOCX / TXT 合同文件，可选输入审查指令（如"帮我审查这份租房合同"），点击发送
3. **查看报告**：审查完成后左侧显示结构化报告，右侧同步展示合同原文的高亮标注。鼠标悬停高亮区域查看风险详情，点击可钉住气泡
4. **思维链**：点击回复上方的思维链标题可展开 / 收起 AI 的工具调用与推理过程
5. **对话管理**：左侧侧边栏支持搜索（拼音首字母 / 全拼 / 中文模糊）、重命名（行内编辑，回车保存）、删除对话
6. **消息操作**：鼠标悬停消息气泡，LLM 回复可复制（纯文本 / Markdown）、重新生成、删除；用户消息可复制、编辑、删除

“复制纯文本”沿用页面的 Markdown 解析及净化规则提取正文，不删除行内反引号或代码块中的内容；保留段落、显式换行、代码缩进、列表编号及嵌套关系，表格按行换行、列间使用制表符。链接取显示文字，图片取替代说明，HTML 实体只按展示语义解码，不复制已被页面移除的脚本或样式。提取使用不挂载页面的文档片段，不改变聊天内容；重新生成期间复制当前展示的预览。选择“复制 Markdown”仍原样复制源文本，两种复制均不改写历史记录。

### 合同上传限制

单个合同文件最大 **10 MiB（10 × 1024 × 1024 字节）**，恰好达到上限允许上传。选择超限文件会在导航栏下方显示浅暖白圆角警告提示，约 3 秒后自动消失，不替换原先已选附件，也不清空输入草稿；发送前会再次校验。

文件选择器及选择 / 发送校验统一支持 **PDF / DOC / DOCX / TXT**，扩展名不区分大小写。DOC 在后端自动转换，无需用户自行处理。不支持或缺少扩展名的文件沿用同一圆角警告，不替换原附件、不清空文字，也不创建会话、调用审查或写入失败问答。大小超限仍优先显示大小提示。选择器过滤只用于便利选择，不能代替校验；前端不依赖可能为空的 MIME、不读取正文来猜测格式，改后缀也不能证明文件有效，实际内容仍由后端独立解析。

后端普通与流式审查接口均独立检查文件大小，最多读取上限加一字节，避免缺失或不准确的大小元数据绕过检查。超限返回 HTTP `413` 及中文提示，不进入文档解析或模型调用；流式接口在开始 SSE 前拒绝请求，前端会识别 HTTP 错误并显示提示。

该限制是单文件业务校验，不是整个 HTTP 请求的接收上限。multipart 解析阶段仍可能将文件写入临时目录；公开部署时还应在反向代理或网关设置请求体大小、并发等资源限制。

### DOC 本地转换配置

在运行后端的服务器安装 LibreOffice，在 `backend/.env` 中配置后重启服务：

```env
# 留空时查找 PATH 和标准 Windows 安装目录；显式配置必须是实际文件的绝对路径。
LIBREOFFICE_PATH=C:/Program Files/LibreOffice/program/soffice.com
DOC_CONVERSION_TIMEOUT_SECONDS=45
# 可选，必须为已存在的可写绝对目录；留空使用系统临时目录。
DOC_CONVERSION_TEMP_DIR=
```

Linux 可指定 `/usr/bin/libreoffice`；Windows 建议使用安装目录的 `program/soffice.com`，不要附加命令参数或额外引号。路径写错不会静默换用其他程序。macOS 可指定安装包内 `Contents/MacOS/soffice` 的绝对路径；当前实际验证环境为 Windows，其他平台仍需自行验证本地安装。

转换在线程池执行，每个后端进程最多同时处理 **2 个 DOC**，超出立即返回 `503 document_converter_busy`，不无限排队；多 worker 的总并发会相应增加。单次转换默认 **45 秒**（允许配置 1—120 秒），超时返回 `504 document_conversion_timeout` 并终止本次进程树。缺少程序、路径不可用或无法创建临时目录返回 `503 document_converter_unavailable`，不伪装为文档损坏；损坏、加密或无法转换的文件返回固定解析提示，不回显内部路径或转换日志。两类上传均在开始模型调用和 SSE 前完成转换。

每次使用独立临时目录、固定内部文件名及独立 LibreOffice 配置，成功或失败后回收自身临时文件；不使用 shell，不把用户文件名拼入命令，不向转换进程继承应用 API Keys，不干扰用户桌面 Office。DOC 先校验 OLE 文件头，转换后检查 DOCX 基本结构；转换产物压缩大小最多 32 MiB、ZIP 声明解压大小最多 64 MiB、最多 2048 个条目，超限返回 `413 converted_document_too_large`。这些检查不等于病毒检测、运行中的磁盘配额或所有上传格式的完整解压防护。

独立配置禁用宏、活动内容、OLE 自动化及文档链接自动更新。但 **headless、文件头校验和上述配置不构成系统安全沙箱**；公开部署仍应将转换器置于低权限、无外网、受限文件访问及 CPU / 内存 / 磁盘配额的隔离环境，及时更新 LibreOffice。进程启动较慢或复杂文档超时时可调整时限，不能以无限等待代替限制。转换后的 Word 共用同一提取与预览链路，重新审查使用已保存的正文和结构，不再次转换附件。

### Word 正文与表格预览

DOCX 按正文中的实际顺序提取段落、表格和单元格内的嵌套表格；合并单元格只读取一次，同时保留行列及合并关系。模型读取的 `raw_text` 仍是统一纯文本，行与段落以换行分隔、单元格以制表符分隔；预览使用解析器生成的 `document_blocks` 展示真正的表格，不从制表符猜测结构，也不让模型自行返回布局。

结构中的 `start` / `end` 使用浏览器一致的 UTF-16 坐标，避免 emoji 等字符导致偏移。前后端上传响应、报告保存、历史读取和合同重新审查均保留同一结构；重审沿用已保存的解析结构，不重新上传附件或采用模型伪造的结构。DOCX 解析通过线程池执行，不在事件循环中同步阻塞其他请求。

风险引文优先精确匹配原文，再尝试忽略空白差异；数字、金额、百分号及英文不再先被丢弃，数字片段也不能误命中更长数字。含数字或拉丁字母的引文匹配失败时不再仅按汉字猜测；其余引文保留汉字模糊回退。跨格 / 跨行风险按文本范围分段，仍共用风险身份，支持统一钉住和取消；表格可独立横向滚动，滚动和窗口尺寸变化会更新钉住气泡的位置。

所有文字均先转义再生成固定表格及标记标签，不执行文档中的 HTML。结构坐标、网格、嵌套和资源预算校验失败时回退显示完整纯文本，不丢弃报告正文；TXT 及未保存结构的数据继续纯文本展示。单个预览结构的限制为 10000 个块及单元格、100000 个表格网格位置、16 层嵌套、每表最多 256 列及 1000 行，超过时只回退预览，不截断模型原文或数据库内容。

该展示保留正文的段落和表格阅读关系，不复刻 Word 页面的字体、分页、精确列宽及行高，也未包含页眉页脚、文本框、图片 OCR、修订记录或自动编号的完整还原。DOC 经本地转换后复用相同逻辑，但转换本身也可能改变原 Word 细节，不能宣称完整还原所有旧文档。测试新表格效果需要重新上传文件，不能从过去未保存的表格内容恢复结构。

### PDF 表格提取与预览

文字 PDF 使用已有 pdfplumber 的线框策略，根据真实单元格边界恢复行列及合并跨度，不额外引入模型。正文与表格按页内位置排序；内层表格归入所属单元格，内表文字不再同时作为外表正文重复追加。最终仍生成 `raw_text` 和 `document_blocks`，共用上述预览、高亮、保存、刷新及重新审查流程。各页之间保留空行，跨页表格按页保留，不自动合表或删除重复表头。

当前不猜测无框线表格，文字仍按纯文本保留。表格交叉、子表跨越多个父单元格、侧栏正文与表格并排、文字跨越格线、字符分配校验失败或超出结构预算时，该页退回原有的整页文本提取结果，不只保留成功识别的部分。结构处理的每页预算包括最多 128 张表、10000 个单元格及 100000 个网格位置，嵌套最多 16 层；这是结构化处理边界，不是 PDF 解码时间或总内存的完整限制。展示不复刻 PDF 的字体、精确尺寸及分页版式，也不能修复源文件本身缺失或错误的字符映射。

暂未接入 OCR。页面没有可提取文字但含图片时，后端在调用模型和建立审查 SSE 之前返回 `400 / pdf_ocr_required`，提示改用有文本层的 PDF 或 DOCX / TXT；混合文档中出现这类页面也拒绝整份审查，避免仅审查前面的可读页。真正的空白页继续跳过。该保护不代表能识别所有扫描情况：同一页同时有可读文字与图片中的条款、或文字已经转为矢量轮廓等情况尚未做完整性判定，不能保证图片中的条款会被提取。

### 历史消息写入

首次保存按一轮问答追加消息；编辑、单条删除及两类重新生成均使用消息 ID 与版本校验进行定点操作，不上传整段历史覆盖数据库。废弃的 `POST /api/conversations/{conv_id}/rebuild` 已移除，返回普通 404，不再出现在 OpenAPI 文档中；对应存储方法、前端封装和旧格式导出工具一并清理，不保留兼容入口。

### 普通咨询重新生成

点击普通回复的“重新生成”，会在原位置展示新内容的临时预览；保留原问题、后续问答及输入草稿和待发附件，不把重跑当作新消息发送。只有服务端完成生成并确认保存后，才替换目标回复及工具过程，消息 ID 不变，刷新不会多出一轮问答。失败、停止或缺少保存确认时撤回预览、保留旧回复；这与普通首次生成停止后保存部分回复的行为不同。其他会话仍可独立发送、停止或重跑。

接口为 `POST /api/conversations/{conv_id}/messages/{message_id}/regenerate_chat/stream`，请求体只需 `{"expected_revision": "目标回复的 revision"}`。服务端读取该回复对应的已保存问题及此前历史，不接收客户端指定的查询或上下文，不将目标旧回复及后续轮次送入模型。使用现有咨询 Agent，不修改提示词或工具调用限制。

完整非空正文及合法结束事件到达后，在同一 SQLite 写事务中复核目标回复和整个输入上下文的身份、版本，再只更新目标正文、过程和会话时间。生成期间问题 / 前文 / 目标被编辑、删除或重建时拒绝覆盖，返回 `reply_changed`；不因标题改名或之后新追加的问答而覆盖这些记录。SSE 的 `done` 在提交之后发送，含 `saved: true`、`message_id`、新 `revision`、`chat_reply`、`thinking_chain` 及实际使用的问题身份和正文。响应丢失不代表没有保存，应重新读取历史核实，不自动用旧快照回写数据库。

普通咨询与合同审查使用不同重跑端点。无法确认对应问题、问题为空，或记录属于合同审查时，在模型调用前拒绝普通重跑并保留记录。当前成对保存于同一事务中连续分配消息 ID，来源校验还要求紧邻用户消息的 ID 连续，避免删掉中间消息后误用更早的问题；旧版分散写入形成 ID 缺口的记录可能需要重新发送问题。旧数据没有独立轮次关联，不能据此证明所有经过旧版重建的历史的原始配对关系，本功能不自动修补或迁移这些历史。

### 历史合同重新生成

点击合同报告下方的“重新生成”，会直接使用该报告已保存的合同原文重新审查，无需再次选择文件。生成期间保留旧报告正文，可查看新的工具调用过程或停止；只有收到服务端保存确认后，才同步替换该报告、风险标注和过程记录。当前输入草稿及已选附件不受影响，切换到其他会话仍可独立发送或重新审查。

会话详情中的消息增加 `id` 和 `revision`，分别用于稳定定位与版本校验，不需要迁移数据库。后端已提供 `POST /api/conversations/{conv_id}/messages/{message_id}/regenerate_contract/stream`，JSON 请求体为 `{"expected_revision": "目标消息的 revision"}`；客户端不必重新上传文件或提交合同全文，服务端直接读取该报告保存的原文。

新报告的结构与原文对应关系通过校验后，在同一 SQLite 事务中仅更新目标助手消息及会话更新时间，不删除原问答、不追加用户消息、不修改后续轮次。SSE 的 `done` 帧在提交成功后才发送，并包含 `message_id`、新 `revision`、`thinking_chain` 和 `saved: true`。模型失败、缺少完整结束帧、格式异常或保存失败时保留旧记录；生成期间原报告被修改、删除或被另一次重跑更新，则拒绝覆盖并返回 `report_changed`。

缺少保存原文的旧记录返回 `contract_source_missing`，才需要重新提供文件。`revision` 只是乐观并发校验，不是身份认证或权限凭证。网络在提交后中断时，未收到完成帧不等于未保存，应重新读取历史确认，不能自动用旧快照覆盖数据库。

页面加载历史时保留消息 ID 与版本；刚生成但尚无 ID 的内存报告，需与已保存的完整消息顺序、目标原文及附加指令一致才能定位，否则提示稍后刷新重试，不猜测相似报告。缺少原文时提示重新上传并保留原报告；失败、停止或未收到完整保存确认时，不用失败消息替换报告。合同与普通咨询分别使用对应的定点重生成接口，均不通过删除原问答来重跑。

编辑、单条删除和两类重跑共用未确认身份的回查规则：响应必须属于请求的会话，整段角色、正文、用户附件名、合同原文及指令一致，消息身份有效且不重复；已经绑定的消息 ID 与版本也必须吻合，核实期间本地内容和身份不得变更。助手回复上用于展示的附件镜像不作为数据库附件字段比较，避免保存回执丢失后明明已写入却无法编辑或删除。无法核实时不猜测重复正文的对应关系，不发起后续变更或模型调用，页面内容及编辑草稿保持原有保护。

### 合同附加审查指令

选择附件后，在输入框填写“重点审查乙方责任”等文字并发送，指令会传入模型，而不只是显示在聊天气泡中。普通和流式审查端点均接受可选的 multipart 字段 `instruction`，省略或只含空白时保持常规审查行为，不要求模型增加报告字段。

前后端先将 CRLF / CR 统一为 LF，再移除首尾空白，保留内部换行；按 Unicode 字符计数，最多 4000 字，不按 UTF-8 字节数或 JavaScript UTF-16 长度计数。前端超限时沿用现有提示，保留原文字和附件，不创建会话或启动模型；后端独立校验，返回 HTTP 422 及 `contract_instruction_too_long`，不开始解析和审查。这个限制只针对附加指令，不是合同原文或普通咨询的长度限制。

模型输入通过 JSON 数据字段区分 `instruction` 和 `raw_text`，都作为用户消息传入；系统提示明确附加要求不能覆盖安全约束、工具边界和报告模板，合同中的命令不作为指令执行。这是输入边界与提示约束，不代表可以彻底消除模型提示注入风险。

非空指令作为报告 `contract_data.instruction` 保存，值来自请求而非模型回显；不新增数据库列、不长期保存原始附件。刷新后重新生成沿用目标报告已保存的原指令，版本及保存确认也校验该指令，避免相同原文、不同审查重点的报告错配。旧报告缺少此字段时按无附加指令处理，不从可编辑的用户气泡推测补全。仅编辑展示气泡不会改写已经保存的审查输入；需要采用新的审查重点时，应随附件重新发送。

### 会话并发与发送防重

发送文本或合同前，同步固定本次文字、附件、历史快照及占位回复。自动命名、创建会话和刷新列表期间切换页面，不会改用另一会话的内容；后台工具步骤和正文更新到各自缓存，切回后恢复。每个尚未创建成功的新对话也有独立临时身份，创建响应逆序返回不会抢占当前页面。

同一会话从准备到保存任务结束保持发送锁，不影响其他会话并发。连续回车或点击旧发送按钮只会忽略重复操作，停止需点击独立停止按钮。请求结束仅清理自己的控制器与缓存。

输入框的普通回车发送，带 Shift / Ctrl / Alt / Meta 的回车不触发发送；中文输入法选词期间的回车不发送文字或附件，也不拦截候选确认的默认行为。按住回车产生的重复按键不发送新草稿，松开后可正常发送。消息编辑期间，用 Esc 取消输入法候选不会退出编辑；非组合输入时 Esc 仍取消编辑。发送、消息编辑和标题重命名共用组合输入判断，识别 `isComposing` 及 `keyCode === 229`；此保护不改变既有会话锁或鼠标发送行为。

整条历史会话确认删除并收到服务端成功响应后，会取消该会话的后台生成或合同重跑，释放它的锁、缓存和草稿；迟到的正文、工具事件、保存响应及历史列表响应不能把已删记录恢复到页面。删除等待期间只阻止目标会话的新发送；若此时模型完成，暂缓追加保存，删除失败后仍可正常完成。取消删除不会停止生成；删除响应未获确认时保留页面并提示刷新核实，不猜测服务端是否已经执行。其他会话的生成、草稿和过程状态不受影响，普通“停止生成”仍保留原有部分回复保存行为。

历史存储在插入消息的同一事务内先取得写锁并确认会话存在，防止“路由校验通过后，另一个请求删除会话”的窗口产生无归属消息。目标已删除时拒绝追加或重建，返回 404；不迁移数据库，也不自动清理已有历史数据。当前页面的消息删除、编辑及两种重生成均采用定点接口，不再调用整段重建；旧重建端点及封装仅保留兼容性。

### 侧边栏重命名

保持行内编辑、回车或失焦保存、Esc 取消的原有交互，中文输入法选词不会误提交；空白和未修改标题不发送请求。各项独立保留编辑草稿和保存任务，回车与失焦不会重复写入，旧保存结果不会关闭其他项的编辑器，也不会清空保存期间继续输入的文字。失败保留页面原标题与草稿，可继续编辑重试；草稿只在当前组件内存中保留，Esc 明确取消、刷新或关闭页面会清空。

标题端点接受可选 `expected_title`，在同一 SQLite 更新语句中比较原标题，提交后返回 `saved: true`、`conversation_id` 与实际 `title`（保留 `ok: true` 兼容字段）。标题已变化返回 `409 / title_changed`，会话已删除返回 404，不误报成功；不迁移数据库，不更改消息及会话排序时间。旧调用可省略条件字段，但不具备条件更新保护。

回执丢失或无效时，只读取目标会话核实，不自动重复写入；已保存则采用确认结果，无法确认则保留草稿并提示先保留文字、再刷新核实。发现其他位置的新标题时保留草稿，再次保存沿用现有确认框，明确确认后才按最新标题条件覆盖；确认期间标题再次变化仍会被拦截。Esc 或组件卸载不等于撤回已发出的写入。自动命名也只允许替换默认的“新对话”，不覆盖用户已自定义的标题。

### 历史读取与列表刷新

快速切换历史、新对话或已缓存对话时，会取消不再需要的历史读取；即使底层仍返回旧结果，也不会替换当前消息、关闭新预览或滚动后来切换的页面。历史列表刷新只采用最近一次发起的有效请求，最新读取失败时保留当前列表，不倒退采用旧快照；创建、删除或本地改名后也会失效之前的列表读取，避免新记录或标题被旧响应抹掉。

历史详情和列表读取使用独立取消控制器，组件卸载会清理两类读取及父信号监听；删除会话只取消同身份的历史读取，不误停其他目标的加载。生成请求可以取消它自己的列表子请求，但取消或替换列表读取不会反向停止模型生成。历史读取失败沿用现有提示样式告知当前页面已保留，日志只记录异常类型、不输出完整请求详情；过期或取消的读取不再产生迟到提示。

侧边栏列表是辅助同步：发送完成必要的会话准备后，不等待列表刷新才调用模型；新增问答保存、消息编辑 / 删除及两类重跑也不等待列表刷新才收尾和解锁。列表慢读或失败不延长生成状态，不把已经确认的保存误判为失败；列表更新可能稍后显示，仍只采用最新有效结果，替换读取和卸载清理规则不变。消息保存确认、历史详情核实及实际写入仍必须等待，不能因为列表改为后台刷新而提前宣称已保存。模型已经启动时点击停止，仍按原规则保存部分回复，不再把它当作“等待列表中的未发送草稿”。

目标历史的会话 ID、消息数组、角色及正文通过校验并完成转换后，才一起切换会话身份、消息和草稿。读取失败或响应异常时保留原页面、合同预览及钉住状态、草稿和附件，重新测量一键到底按钮而不强行滚动。读取等待不允许新发送或提交消息编辑，但不暂停仍显示页面的生成过程或丢失新创建会话的真实身份；目标加载成功后再切换显示，后台更新仍按各自会话隔离。

原页面的消息编辑器在历史读取等待期间保持显示，可以继续修改文字或取消编辑；只有目标成功加载后才切换到目标的编辑状态。读取失败后可直接继续保存原编辑，无需重新点击编辑按钮。等待期间已经发出的编辑保存仍按原目标收尾：保存成功正常关闭编辑器，保存失败保留编辑文字；被新对话或其他历史取代的迟到读取不会恢复或关闭后来页面的编辑器。编辑草稿仍仅保存在当前页面内存，不自动保存或写入新目标。

欢迎页提示仅用于展示，不进入消息数组或数据库。已移除旧占位欢迎语的兼容过滤，历史读取不再按欢迎语或产品名隐藏消息；已存内容按原顺序展示并作为后续咨询上下文，不自动清洗数据库。

### 消息滚动与一键到底

打开数据库历史或恢复内存中的对话，都在 DOM 更新并复核页面归属后定位到底部；等待期间切到新对话，不会滚动后来打开的页面。缓存中未确认保存的正文仍保留，不为滚动定位重新读取或覆盖它。

距底部超过 100px 才显示一键到底按钮，点击到底立即隐藏。除滚动事件外，也观察当前消息容器和消息行尺寸；窗口缩放、文字换行、展开工具结果等变化后，无需额外滚动就能更新按钮。消息增删及时调整观察对象，切换容器或卸载清理观察器及排队任务，不修改页面样式、不改变生成时原有的滚动跟随策略。

### 逐字动画与后台输出

每个页面组件独立管理逐字动画，同一页面内各条回复保持独立队列，正常显示速度不变。切换到其他对话后，旧对话剩余队列在下一帧一次补齐并停掉动画，后台新片段直接加入完整正文，不滚动当前对话。

组件卸载时立即补齐已经收到的文字，并清理本组件全部逐字定时器；后续片段不再重启动画，不影响其他页面实例。该处理只释放显示动画，不丢弃已接收正文、不改变重新生成的保存确认规则，也不顺带取消模型请求。实际关闭或刷新网页时，网络仍受浏览器连接生命周期约束，这不代表支持离线后台生成、断线续传或刷新后恢复未保存内容。

### 单条消息删除

确认框固定所点消息及所属会话，切换页面后也不会误删其他气泡；只有服务端确认后才从页面和所属缓存移除。删除正在生成的 AI 回复，会停止这一轮生成并保留用户问题及附件消息；删除正在生成这一轮的用户问题，也会停止该轮，但保留已收到的回复。删除旧历史气泡不会停止同会话正在生成的新一轮，其他会话可继续独立发送。删除重跑中的合同报告会停止该报告重跑，不连带删除用户消息。

后端提供 `DELETE /api/conversations/{conv_id}/messages/{message_id}`，JSON 请求体为 `{"expected_revision": "目标消息的 revision"}`。在同一 SQLite 写事务内校验会话归属和版本，只删除目标，不重建其他消息；目标不存在返回 404，版本冲突返回 409 及 `message_changed`。成功返回 `message_id` 与 `conversation_deleted`；最后一条消息删除后同时清理空会话。

若同会话还有未落库的其他消息，前端附加 `preserve_empty_conversation: true` 暂留会话容器，避免误停后续生成；该回复保存未获确认时，不擅自清空其页面内容。普通保存接口额外返回本次两条消息的 `id`、`role` 与 `revision` 回执，只绑定所属请求对象。删除在途回复先等待其停止及保存确认，再删除指定消息，避免迟到的保存重新追加它；旧回执缺少身份时，只有完整消息顺序、内容和合同输入一致才允许回查定位，不能猜测重复正文。

取消确认不停止生成；确认后若删除失败或响应丢失，保留消息并提示刷新核实，已经停止的生成不会自动重跑。页面生命周期内过滤迟到历史响应中的已确认删除身份；不自动重试删除，不以旧快照覆盖服务器记录。`revision` 是乐观并发校验，不代表用户认证。附件消息保留文件名及当前内存引用，不增加原始附件的长期存储。

创建会话失败或在发送准备阶段取消时，撤回本次尚未提交的消息占位，恢复原始文字（保留空白和换行）及原附件，提示后可直接重试，不写入假的模型失败回复。创建、自动命名和列表刷新均支持取消；一旦已经发起咨询 / 审查请求，停止仍沿用保存部分回复的行为，不自动重新发送。

若原位置已有更新的草稿，旧待发内容会暂存而非覆盖或合并。发送或清空现有草稿后，重新打开原会话可恢复暂存内容；尚未创建成功的会话则点击“新对话”恢复。多个失败草稿依次恢复，不跨会话挪用。草稿和暂存附件只保存在当前页面内存中，刷新后清空；本功能不增加原始附件的长期存储。

### 用户消息编辑与版本核实

后端已提供 `PATCH /api/conversations/{conv_id}/messages/{message_id}`，请求体为 `{"expected_revision": "目标消息的 revision", "content": "修改后的正文"}`。仅允许编辑用户消息，在同一写事务内检查会话、消息归属和预期版本，再定点更新正文；不重建历史、不调用模型、不改变附件名、报告原文、审查指令或后续问答。正文保留原始空白和换行，兼容原有空字符串行为。

事务提交后返回 `message_id`、新 `revision`、已保存的 `content` 和 `saved: true`。目标不存在返回 404，编辑助手消息返回 400 及 `message_not_editable`，版本冲突返回 409 及 `message_changed`；额外提交角色、附件或报告字段返回 422。失败时正文和会话更新时间整体回滚。版本校验不是身份认证，响应丢失不代表未保存，页面会读取最新记录核实，不盲目重复提交。

页面保存编辑时固定所属会话、目标消息、原始正文及版本；确认保存前不提前改写原气泡，也不调用整段重建。版本冲突时只在后台读取最新记录，不刷新整个网页：正文未变、结果已一致或保守改动范围互不相交时可自动核实 / 合并，最多重试一次。范围重叠、同位置插入等不能确定的修改，保留用户编辑文字，提示已有新版本；再次点击保存可在现有圆角毛玻璃确认框中查看最新正文，选择“覆盖保存”或“返回编辑”。明确覆盖仍带版本校验，不能越过之后的新修改。

消息尚未落库时，保存编辑会等待原轮次生成和保存结束，不停止模型、不改变已经发送的模型输入；等待期间可取消编辑，尚未提交的修改不会在完成后悄悄写入。发送准备失败时，修改文字进入既有草稿恢复队列，不覆盖原草稿。已经提交的保存不能通过“取消”撤销，需等待确认结果。编辑旧消息不停止同会话后续生成，其他会话仍可独立发送。

保存失败保留原消息与编辑文字，切换会话再回来可继续编辑；收到明确保存确认后才更新所属消息和版本，迟到的旧历史响应不能恢复旧正文。编辑草稿仅在当前页面内存保留，刷新或关闭页面会清空，不增加原附件的长期存储。只保存展示文字、不自动重新生成回答，合同报告的原文与已保存审查重点也不随用户气泡编辑改变。

### 流式异常与保存确认

咨询、合同审查和原文重跑共用 SSE 读取器，支持分包、中文跨字节、LF / CRLF / CR 换行、多行 `data` 及 EOF 尾帧。首次正常完成、错误或主动停止后不再处理后续正文及重复终止事件，并等待对应异步回调完成，关闭读取器、取消网络连接并释放定时器和事件监听。

没有合法结束帧、JSON / 字段异常或响应并非 SSE 时，页面保留已收到的正文并附加明确提示；普通消息只保存一次。合同报告还需通过完整字段检查才展示风险标注卡片，不把残缺结束帧当成完整报告。历史合同重跑仍须服务端保存确认后才替换旧报告。

默认在等待响应头或下一批数据超过 **180 秒**时报告空闲超时，配置位于 `frontend/src/utils/sse.js` 的 `SSE_IDLE_TIMEOUT_MS`。该时间不计算本地回调或保存耗时，也不是整个复杂审查流程的总时长限制；收到心跳或新数据后继续等待。

单个 SSE 事件累计的行内容最多 **16 MiB**（`SSE_MAX_FRAME_BYTES`），按 UTF-8 字节计数，包含 `data` 前缀、注释及未知字段，不计换行分隔符；只有空行结束事件才重置额度。网络分包会分段解码，既阻止无换行长行、多行未结束事件无限累积，也不把同一网络分包内的多个合法事件误当作一个大事件。这不是合同上传大小、输入字数或整段回复的总长度限制，不静默截断合同原文和报告。

超限后只报告一次“单次回复数据过大，已停止接收，请刷新会话核实结果。”，取消连接并释放读锁。首次生成保留已收到正文，附加提示后按原流程保存一次；普通咨询及合同重新生成撤回临时预览、暂保留旧回复，不追加问答或自动重试。超大的完成事件可能已在服务端提交，页面未收到完整回执不能证明保存失败，应重新读取历史核实。该限制仅约束前端 SSE 解析缓冲，不代替 HTTP 错误响应、服务端输出、已展示内容总量或部署网关的资源限制；持续心跳但无应用进展的治理仍待评估。

四类流式接口遇到 HTTP 非成功响应时，错误体单独按实际 UTF-8 字节累计，最多接受 **64 KiB**（`HTTP_ERROR_MAX_BODY_BYTES`），不依赖 `Content-Length`，也不直接整包调用 `response.json()`。超限、JSON 或 UTF-8 损坏时只保留“请求失败（HTTP 状态码）”，不显示截断的错误页内容；限内合法的后端安全提示保持原样。超限会取消读取，超时或主动停止沿用原有分类，并清理读锁及计时器；每收到一批新数据重置空闲计时，不把整个错误体读取时长误作空闲时间。

这项额度只约束流式接口错误体的应用层累计与解析，不是合同原文、用户输入或正常回复的长度限制，也不承诺浏览器底层缓冲或实际网络流量始终小于 64 KiB。普通 Axios 请求、服务端及网关的响应资源边界仍需单独评估。

四类流式接口遇到 HTTP 非成功响应时，错误体单独按实际 UTF-8 字节累计，最多接受 **64 KiB**（`HTTP_ERROR_MAX_BODY_BYTES`），不依赖 `Content-Length`，也不直接整包调用 `response.json()`。超限、JSON 或 UTF-8 损坏时只保留“请求失败（HTTP 状态码）”，不显示截断的错误页内容；限内合法的后端安全提示保持原样。超限会取消读取，超时或主动停止沿用原有分类，并清理读锁及计时器；每收到一批新数据重置空闲计时，不把整个错误体读取时长误作空闲时间。

这项额度只约束流式接口错误体的应用层累计与解析，不是合同原文、用户输入或正常回复的长度限制，也不承诺浏览器底层缓冲或实际网络流量始终小于 64 KiB。普通 Axios 请求、服务端及网关的响应资源边界仍需单独评估。

保存请求失败或确认丢失时，不再误报模型断网，也不自动重试写入，避免服务端已提交却重复追加消息。回复保留在所属会话的内存缓存中，切走再回来仍可复制并会再次提示未确认保存。请先复制重要内容，再刷新确认服务器结果；刷新会清空尚未确认的本地缓存。列表刷新失败不等于消息保存失败。

普通新增问答保存还必须收到 `ok: true` 和本轮按用户、助手顺序排列的两个有效身份：消息 ID 为不同的正整数，`revision` 为 64 位小写十六进制字符串。HTTP 成功、单独的 `ok: true`、缺失成功标记或不完整身份均不算保存确认；沿用上述提示和缓存保留，不改正文、不部分绑定身份、不自动重试。后续另一轮保存成功不清除此前的未确认内容，其他会话的生成和锁不受影响。

若未确认回复能与服务器记录安全对齐，并由用户手动重新生成或重新审查，收到完整保存确认后仅解除目标回复的未确认标记。会话中没有其他未确认回复时释放该缓存，再次打开时正常读取历史，不重复显示过期警告；其他未确认回复仍保留。重跑失败、停止或回执不完整时，原内容、标记及缓存均不清除；这不是自动重试新增问答。

### 确认框与组件卸载

删除会话、删除单条消息及编辑冲突覆盖共用确认框，同时只保留一个提示，不用新请求覆盖旧等待者。组件卸载时，仍在等待选择的操作按取消收尾；即使刚点击确认、但操作尚未开始，也不会在卸载后迟到提交删除或覆盖。这里的卸载不是侧边栏内切换对话，切换对话仍按原先固定的目标确认。

已发出的网络请求可能已经提交，关闭确认框或卸载组件不等于服务端回滚，本机制不会自动补偿或重试写入，也不顺带停止模型生成。确认框的圆角、毛玻璃及按钮样式保持不变。

### 合同预览分隔条

宽屏下使用鼠标左键拖动分隔条调整聊天与合同预览比例，范围保持为 25%—75%。鼠标释放、浏览器窗口失焦、关闭预览、切到窄屏或组件卸载时，统一撤销拖拽监听和待执行动画，恢复拖拽前的光标与文字选择样式；重复开始或结束不会叠加处理。该清理仅结束拖拽交互，不停止模型生成或其他会话的并发请求。

### 动态内容安全边界

用户消息、历史消息和模型回复的 Markdown 在解析后通过 DOMPurify 白名单净化，保留标题、列表、表格、代码块等常用格式，移除脚本、事件属性、危险链接、表单和自定义样式。正文不能借用页面布局类名，代码块可保留语言标记。此处理仅影响展示，不改写数据库内容或 Markdown 复制结果。

合同原文始终按纯文本转义，不将文档中的 HTML 当成标签执行；高亮先在原文上定位，再转义对应文本，避免实体字符长度变化影响坐标。仅由应用生成 `mark`、风险等级和气泡属性，气泡通过 `textContent` 显示，保留文字选择及复制。

高亮模糊定位仍采用汉字精确匹配优先、最长公共子串回退的规则，不改变匹配阈值或同长时优先选择原文较早范围的行为。回退算法使用单行滚动数组，动态规划的辅助空间从合同汉字数与引文汉字数的乘积降为只随引文长度增长，避免长合同为每个风险点建立庞大的二维表；这不是对合同截断或减少风险点。最坏计算时间仍与两者乘积有关，不代表已经解决任意超长文本的全部性能问题。

这不是完整的公开部署安全方案：正常图片和链接仍可指向外部地址；身份认证、访问控制、请求资源限制及部署层安全策略需另行配置。

## 常见问题

**Q: 启动后端时报错 `ModuleNotFoundError`？**
A: 确认已激活虚拟环境并执行 `pip install -r requirements.txt`。

**Q: 合同审查返回"⚠️ 合同审查失败"？**
A: 通常是因为 DeepSeek API Key 未配置或额度耗尽，检查 `.env` 文件。

**Q: 法律问答搜不到某条法条？**
A: 当前向量模型为 Qwen3-Embedding-8B Q4 量化版，部分精确查询依赖 BM25 和 ArticleMap 兜底。如仍检索不到，可能是该法条未包含在 data/ 目录的法律文本中。

**Q: 前端页面空白？**
A: 确认后端已启动（http://localhost:8000/docs 可访问），且前端 Vite 代理配置正确。
